# Startup Script (Optional)

To automate the setup of your GCP Virtual Machine for use with Google Colab, you can combine the provided phases into a single bash script. If you are using this as a GCP Startup Script (in the VM metadata), it will run automatically every time the instance boots.

#### Automation Script

This script performs the system updates, environment configuration, and server launch described in your documentation.

<a class="button secondary"></a>Bash

```bash
#!/bin/bash

# 1. Update System & Install Python/Pip [cite: 5, 8, 9]
# Ensures package lists are fresh and build tools are available[cite: 6].
apt update
apt install -y python3 python3-pip python3-venv

# 2. Create a Virtual Environment [cite: 10, 14]
# Isolated environment to prevent system-wide pip install errors[cite: 11].
python3 -m venv /opt/colab-env

# 3. Install Colab Connectivity Tools [cite: 18, 21, 22]
# Install Jupyter and the required websocket extension within the environment[cite: 19].
/opt/colab-env/bin/pip install jupyter jupyter_http_over_ws
/opt/colab-env/bin/jupyter serverextension enable --py jupyter_http_over_ws

# 4. Start the Jupyter Server [cite: 24, 27-32]
# The server is launched in the background (&) and configured to trust Colab[cite: 25].
# --allow-root is added as startup scripts run with root privileges.
/opt/colab-env/bin/jupyter notebook \
  --NotebookApp.allow_origin='https://colab.research.google.com' \
  --port=8888 \
  --NotebookApp.port_retries=0 \
  --NotebookApp.allow_credentials=True \
  --no-browser \
  --allow-root &
```

#### Key Implementation Details

* Permissions: When running as a startup script, the commands execute as the root user. Therefore, `sudo` is removed from the internal commands, and `--allow-root` is added to the Jupyter launch command to prevent permission errors.
*   Persistent Paths: The virtual environment is created in `/opt/colab-env` to ensure it is accessible system-wide rather than tucked into a specific user's home directory.

    <a class="button secondary"></a>
* Background Execution: The `&` at the end of the Jupyter command ensures the script completes its execution while the server continues to run in the background, listening for connections.
*   Security: This script enables the necessary `jupyter_http_over_ws` extension required for Colab to communicate with the local runtime securely through the SSH tunnel.

    <a class="button secondary"></a>

#### Next Steps after Script Execution

Once the VM is running this script, you must still perform the local connection steps:

1.  Retrieve Token: You will need to check the logs (e.g., `sudo journalctl -u google-startup-scripts.service`) to find the unique token URL generated by the Jupyter server.

    <a class="button secondary"></a>
2. Establish Tunnel: Run the `gcloud compute ssh` command on your local machine to pipe port 8888.
3.  Connect: Paste the token URL into the "Connect to local runtime" dialog in Google Colab.

    <a class="button secondary"></a>
